## Что остаётся до итогового решения

- Получить ответы владельца о формуле outage и группах UE; до этого их значения не выдумывать и не включать в пакет.
- На другой машине перепроверить текущую версию физических расчётов и получить новый допуск Stage 2; старый допуск относится к другим исходникам и реестру.
- Закончить аудит исторических запусков и безопасно выделить независимые ID для обучения, настройки, теста и итогового сравнения.
- Измерить время и память на целевой машине. Полный пилот, включая 2500 и 5000 UE, здесь не запускать.
- Собрать реальные данные с разными нагрузками и типами трафика, затем независимо оценить все четыре модели и проверить невиденные при обучении нагрузки.
- Выбрать правила Adaptive только по реальным данным; до этого обычная модель остаётся закрытой, а development-модель служит отладке.
- Провести парные сравнения Static, Adaptive-P и Adaptive-RA/DT в согласованном бюджете; подготовить результаты и доверительные интервалы.
- Пройти полный регрессионный набор текущей версии на другой машине с согласованным лимитом времени и памяти.
- Сверить результаты с §47 и обновить статусы карты §50 по фактическим численным опытам, затем проверить воспроизводимость пакета на машине коллеги.
- Подготовить итоговый научный отчёт и переносимый комплект. Публикация нового релиза остаётся отдельным шагом после проверки результатов.

## Артефакты итоговой приёмки

`tests/TestFullAdaptiveChain.m` и `experiments/runFinalAcceptance.m` созданы. Последний сверяет наличие файлов итоговых доказательств и их SHA-256; он не запускает симуляции и не выносит научное решение. `TestFinalAcceptance` прошёл 6/6 и в рабочей копии, и внутри переносимого комплекта (`verification/local/checks-final-acceptance-post-package-20261013/`, `verification/local/checks-final-acceptance-packaged-20261013/`); `checkcode` исполнителя и теста — 0 замечаний (`verification/local/checkcode-final-acceptance-post-package-20261013/`).

Шаблон списка доказательств: [`final-acceptance-evidence.template.json`](final-acceptance-evidence.template.json). Для проверки заполненного списка на своей копии проекта:

```matlab
setupProject();
options = struct( ...
    'projectRoot', pwd, ...
    'evidenceManifest', 'verification/completion/final-acceptance-evidence.json', ...
    'outputFolder', 'verification/completion/final-acceptance-review');
report = runFinalAcceptance(options);
```

Для каждого пункта нужно указать ключ, относительный путь внутри проекта и SHA-256 файла. Требуются ровно эти категории:

| Ключ | Что приложить |
|---|---|
| `stage2Revalidation` | Новый допуск Stage 2, относящийся к текущему коду |
| `independentModelEvaluation` | Реальные независимые данные, метрики четырёх моделей и сведения о разделении ID |
| `comparisonSweep` | Завершённые парные результаты трёх методов, сводки и проверку файлов |
| `fullRegression` | Результат полного набора тестов текущей версии |
| `section47Audit` | Итоговую сверку сохранённых параметров и результатов по §47 |
| `section50Audit` | Обновлённую карту требований §50 с фактическими доказательствами |
| `colleagueReproduction` | Команды, версию MATLAB и результат повторного запуска на машине коллеги |
| `releasePackage` | Проверенный переносимый комплект с manifest и контрольными суммами |

Каждый пункт списка — объект JSON с полями `key`, `path`, `sha256`; хеш можно получить функцией `nbiot.ml.fileSha256`. Сначала вручную убедитесь, что сами материалы научно корректны. Статус `ready-for-human-review` означает только совпадение файлов и хешей; единственные финальные статусы программы — `incomplete`, `integrity-error` и `ready-for-human-review`, статуса «принято» нет. Для повторного запуска выберите новую папку отчёта: существующие отчёты не перезаписываются.

`docs/final-report.md` содержит предварительный отчёт: только фактически выполненные короткие проверки и открытые внешние этапы. Завершённый научный отчёт остаётся открытым до получения внешних данных и результатов.
