## Историческая оценка полного объёма — не оценка остатка

Это оценка по объёму кода и проверок, **не измеренное обещание скорости агента**. После первой пары R1+D1 координатор пересчитывает прогноз по фактическому темпу и числу исправлений reviewer.

| Блок | Сумма активных часов агентов, включая ревью |
|---|---:|
| R1–R4 | 27–41 |
| D1–D4 | 23–32 |
| U1–U5,T1–T3 без расширенной U3a | 34–55 |
| P0 и интеграционная координация | 4–8 |
| Всего | **88–136** |

С двумя исполнителями и reviewer: обновлённый ориентир **56–90 часов активной работы сессий**, то есть примерно **7–12 рабочих дней по 8 часов**. Дополнения U4/U5 добавляют 8–12 ч реализации и 2–4 ч ревью; публикация v3 уже сделана и повторно сюда не включена. Сумма часов агентов больше прошедшего времени из-за параллельности; делить её на четыре неправильно — есть последовательные зависимости и единая очередь MATLAB.

Для слабо рассуждающих исполнителей разумный резерв — **до 80–125 часов прошедшего рабочего времени**, если понадобятся дополнительные исправления интеграции. При превышении верхней оценки отдельной задачи на 50% координатор сообщает причину и обновляет срок; не продолжает молча ждать.

Не включены: ожидание решения U3/научных порогов, буквальное расширение физического профиля, внешние большие расчёты/научный разбор. Небольшой перенос GUI в App Designer при необходимости: дополнительно ориентир 4–12 ч и доступ к редактору; иные PHY-параметры оценивать после определения диапазона.

Первый результат R1+D1: ориентир **6–10 часов**, включая первую проверку/ревью. После него будет ясно, устранено ли выявленное узкое место. Ускорение больших нагрузок в N раз без замера не обещать.
