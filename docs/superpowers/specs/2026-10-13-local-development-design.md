# Продолжение NB-IoT на двух машинах

Дата: 13 октября 2026. Основание: явное решение владельца перенести очень долгие расчёты, включая 2500/5000 UE, на другую машину и подготовить оставшуюся реализацию здесь. Это изменение порядка работ ранее согласованного проекта.

## Цель и границы

Подготовить работающую программу со сборкой данных, четырьмя моделями оценки нагрузки, двумя методами автоматического управления, сравнением и интерфейсом. Здесь подтвердить поведение короткими проверками. Реальные данные, точность и эффективность на больших нагрузках подтвердить отдельно на второй машине.

Полный бюджетный пилот Stage 3 не должен блокировать реализацию модулей Stage 4–8. Он остаётся обязательным для оценки большой серии. Ни один результат малого примера не заменяет требования ТЗ к горизонту, нагрузкам и независимым реализациям.

## Распределение работы

| Текущая машина | Другая машина |
|---|---|
| Изучение сохранённых MAT/CSV/журналов | Полный пилот 100/500/1000/2500/5000 UE и память |
| Разработка и небольшие функциональные тесты | Сбор независимых train/validation/test данных |
| Проверка обучения, экспорта и загрузки моделей на небольшом наборе | Обучение на представительном наборе и оценка качества |
| Короткая физическая цепочка Static/Adaptive | Основное парное сравнение трёх методов |
| GUI, графики сохранённых результатов, переносимый комплект | Большая физическая матрица, воспроизведение и приёмка |

Для местной разработки принимаем до 10 UE, до 5 минут на одну проверку и до 15 минут на выбранный набор. Более долгую работу планируем отдельно для второй машины; фоновые часы расчётов на текущей машине запрещены по умолчанию. Время — предохранительный лимит, не обещание продолжительности неизвестных функций.

## Архитектура и данные

Сохраняем одно физическое ядро. ML получает только закрытое прошлое окно базовой станции; целевой показатель — `meanRaUe`, окно 500 мс. ID/время используются для соединения и группировки, не для обучения. Истинные состояния устройств остаются ответами/диагностикой.

Все случаи одного внешнего ID принадлежат одной группе train/validation/test. ID 1064 и прежние diagnostic/development ID не выделяем заново в независимую оценку. Четыре сохранённых размера с ID 1064 подходят для разработки конвейера, но не для доказательства точности модели.

Четыре метода: Linear Regression, Decision Tree, Random Forest и Gradient Boosting. Обучение — на train, выбор параметров — на validation, окончательная оценка — на независимом test. Statistics and Machine Learning Toolbox проверяется перед использованием, установка/оплата автоматически не выполняется. Static сохраняет зависимости MATLAB R2025b + LTE Toolbox.

Контроллер работает каждые 500 мс. Adaptive-P меняет только вероятность доступа; Adaptive-RA/DT — только долю ресурсов 10/90, 20/80 или 30/70. Стартовая конфигурация неизменна, runtime-действие и история отдельны. Принятые назначения не отменяются; невозможное изменение отклоняется с причиной. После горизонта управление не применяется.

Интерфейс использует `SimulationSession` поверх того же ядра; визуализация не влияет на случайные входы и порядок событий. Сохраняется различие полной, остановленной и ошибочной работы. Пауза живой сессии не обещает дисковое продолжение прерванного расчёта.

## Приёмка и перенос

У каждого модуля два статуса: реализация/короткая проверка и независимая научная проверка. Синтетические таблицы маркируются как проверочные и не допускаются в итоговый научный отчёт.

Комплект передачи содержит исходники с хешами, калибровку, тестовые входы, роли ID, параметры серий, пакеты моделей и инструкции. Общий реестр имеет одного писателя: офлайн-копии не расходуют одни ID независимо. Сохраняем старые результаты и `.staging-*`; новая версия кода не возобновляет несовместимый случай.

На второй машине сначала среда и короткий пример, затем явный ресурсный бюджет и долгие серии. Версия/модель/калибровка/внешние ID фиксируются до сравнения. Полученные результаты сначала проверяются, затем включаются в отчёт. Новый релиз публикуется только в отдельно разрешённом сценарии.

## Критерий этого изменения

Новый маршрут, текущий статус и бюджет согласованы между документами; старые инструкции не требуют запускать долгий пилот здесь до дальнейшей разработки. В этом запросе создаём план и документацию, без реализации будущих модулей и без запуска MATLAB.
