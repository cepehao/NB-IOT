# Небольшие эксперименты v3

Все примеры ниже: **Static, одно устройство, 5000 мс модельного времени**, хорошие условия связи из startDemo. Предел текущего UI — 10 устройств и 300 секунд реального расчёта. Большие эксперименты не нужны для знакомства с программой.

## Базовый запуск

```matlab
setupProject();
startDemo;
```

Нажмите «Запуск». Ожидается completed, создано 1, доставлено 1, полезный объём 1600 бит = 200 байт. На карте звезда — станция, точка — устройство. Пауза/Продолжить приостанавливают и продолжают текущий расчёт. Сводка находится на вкладке «Текущий запуск», графики — на «Графики запуска».

## Три изменения одного сценария

После каждого расчёта сначала сохраните нужный результат, затем нажмите «Сброс». Сброс очищает текущую сессию и сохраняет поля настроек; файлы на диске остаются. Проверьте перед каждым запуском одну строку таблицы ниже.

| Случай | Тип трафика | Период, мс | Размер, байт | P | Доля RA/DT |
|---|---|---:|---:|---:|---|
| A: регулярные сообщения | periodic | 1000 | 200 | 1 | 10/90 |
| B: отсрочка подключения | periodic | 1000 | 200 | 0.1 | 10/90 |
| C: другой бюджет ресурсов | periodic | 1000 | 200 | 1 | 30/70 |

На вкладке «Сеть» каждый раз оставьте **1 UE, 5000 мс**, режим Static. На вкладке «Трафик» меняйте верхнее поле **«Период, мс»**, не нижнее **«Период доступа, мс» = 80**. Геометрию и канал оставьте как в startDemo.

- **A:** датчик создаёт сообщение каждую секунду. Посмотрите число созданных/доставленных и график задержки.
- **B:** вероятность попытки P=0.1 заставляет устройство пропускать часть возможностей подключения. Сравните очередь и доставку с A. Для одного устройства это демонстрация ожидания; пользу при массовом доступе так не доказать.
- **C:** RA — служебное подключение, DT — передача данных. Изменяется бюджет доступных ресурсов для этих этапов. Сравните с A, а не с B: P в A/C одинаков.

Во время репетиции A/B/C наблюдались соответственно 4/2/4 доставленных из 5 созданных. Это единичные наблюдения через UI, не статистическое доказательство и не отдельные полные файлы результатов в архиве. Сохраняйте свои запуски для воспроизводимого сравнения. Изменение других настроек может изменить результат.

## Как читать сводку

`completed` — закончился заданный горизонт, а не обязательно все сообщения доставлены. Создано = доставлено + отброшено + ещё в работе. «Ещё в работе» означает, что исход неизвестен на конце наблюдения, не обещание будущей доставки. Успешное подключение не равно доставке всех данных.

Графики строятся по окнам 500 мс. Один пакет 200 байт за такое окно даёт 3200 бит/с **средней доставки за окно**; это не мгновенная скорость радиопередачи отдельного устройства. Пустое окно доставки может сопровождаться ожиданием/передачей частей пакета.

## Сохранить и сравнить

1. «Сохранить» → выберите папку для нового результата. Внутри создаётся отдельная папка запуска.
2. «Сохранённые результаты» → «Экспортировать графики PNG» → выберите родительскую папку. Появится `nbiot-charts-ДАТА-ВРЕМЯ` с 8 картинками. Чёрная пустая таблица этой вкладки сама от экспорта не заполняется.
3. Для сравнения откройте **один или несколько `*_kpi.csv`** кнопкой «Открыть/сравнить KPI CSV». `*_summary.csv` — итоговые числа; эта кнопка для него не предназначена.

## Длительные научные эксперименты

Скрипты в experiments включены как исходный код, но не вызывайте runStaticSweep/runLoadPilot без параметров: их defaults включают большие нагрузки. Внешний Adaptive пока не имеет завершённого пути допуска модели; полный переносимый научный pipeline остаётся доработкой. Протокол, реестр независимых ID, калибровка и бюджет обязательны для отдельной большой серии. См. docs/v3-status.md и docs/comparison-protocol.md.
