# Передача проекта на другую машину

Этот документ описывает будущую передачу на другую машину. Он не управляет текущим вариантом 2 на этом ПК: владелец разрешил свежую Stage 2 проверку и четыре предварительные нагрузки по [плану варианта 2](superpowers/plans/2026-10-14-variant-2-local-validation-and-load-probe.md). На другой машине и для иных объёмов запуск остаётся отложенным до отдельного решения владельца.

## Состояние комплекта

Для передачи на другую машину используйте только пакет с соседним отчётом о сборке. Он фиксирует исходники и калибровку, но остаётся черновиком: `readyForExecution=false`, `requiresStage2Revalidation=true`. Текущий пакет варианта 2 описывает 100/500/1000/2500 UE; его manifest не резервирует ID и сам по себе не разрешает запуск на другой машине.

Старые каталоги `stage3-static-plan-draft-20261013-*` не являются текущим комплектом. Используйте только пакет, который указан в соседнем отчёте о сборке; сверяйте `codeManifestSha256`, SHA-256 калибровки и список файлов в его `manifest.json`. Пакет — снимок рабочей копии, включая незакоммиченные изменения; он не является подтверждённым физическим релизом.

Старый допуск Stage 2 не относится к текущему коду: хеши исходников, доказательств и реестра не совпадают. Поэтому сначала нужна новая проверка Stage 2 на распакованной копии. Она ограничена 10 UE, но включает 232 случая: 150 диагностик столкновений, 80 проверок радиоприёма и 2 набора контрольного воспроизведения. Это отдельная физическая серия; не запускайте её, пока не будет согласован отдельный бюджет времени на целевой машине.

## Отдельная проверка для другой машины

1. Распаковать комплект и открыть папку `project` в MATLAB R2025b. Проверить наличие LTE Toolbox и выполнить `setupProject()`.
2. В PowerShell из корня распакованного проекта сначала проверить, что запуск без лимитов закрыт. Команда должна завершиться сообщением `ExecutionBudget` до запуска MATLAB:

   ```powershell
   .\verification\completion\stage-2\runStage2Physical.ps1
   ```

3. До физической серии запустить на этой машине свежие targeted-проверки из MATLAB и сохранить отдельный журнал:

   ```matlab
   setupProject();
   addpath('verification/completion/stage-2');
   diary('verification/completion/stage-2/targeted-r2025b.log');
   stage2Targeted();
   diary off;
   ```

   Журнал должен содержать MATLAB R2025b, LTE Toolbox и `STAGE2_TARGETED total=38 passed=38 failed=0 incomplete=0`. Только после отдельного решения о времени физического запуска укажите этот журнал и конечные лимиты:

   ```powershell
   $targetLog = 'C:\absolute\path\to\targeted-r2025b.log'
   .\verification\completion\stage-2\runStage2Physical.ps1 `
     -ExecutionProfile external-machine `
     -MaxCaseSeconds <секунд_на_случай> `
     -MaxSuiteSeconds <не_меньше_232_лимитов> `
     -TargetedLog $targetLog
   ```

   Запускатель проверяет общий лимит и закрытые другие MATLAB-процессы, использует свежие ID в реестре только распакованной копии и завершает свой процесс с потомками при hard timeout. Максимум этой проверки — 10 UE, предел запускателя — 10 суток. Для текущего локального варианта 2 применяются команды и безопасный resume из [local-checks.md](local-checks.md); не переносите сюда локальный бюджет автоматически.

4. Найти физический отчёт в `physical-evidence\report.mat` внутри `host-run-*`, путь напечатан как `STAGE2_PHYSICAL_EVIDENCE`. После просмотра targeted-журнала и физического отчёта записать допуск:

   ```matlab
   review = struct( ...
    'reviewer', '<имя проверяющего>', ...
    'scope', {{'targeted-tests','physical-results','limitations'}}, ...
    'notes', '<заметки по тестам, результатам и ограничениям>');
physicalReport = 'verification/completion/stage-2/host-run-.../physical-evidence/report.mat';
acceptance = acceptStage2Evidence( ...
    'verification/completion/stage-2/targeted-r2025b.log', physicalReport, ...
       review);
   ```

   Не редактировать старый `acceptance.json` вручную и не переносить его из другой копии.

## Manifest, роли ID и чтение результатов

Перед запуском сначала сверьте в `manifest.json` версию MATLAB, список файлов и их хеши, калибровку, матрицу случаев, `resourceBudget`, `resourceStatus`, `idAssignments` и `readyForExecution`. Отсутствующий бюджет или пустой список ID означает, что запуск не готов: назначьте ответственного за запись реестра и получите отдельное согласование лимитов до начала серии. Не вписывайте машину, память, время или назначенные ID по предположению.

В реестре ролями ID являются `stage-2-collision-diagnostics`, `stage-2-receiver-diagnostics`, `stage-3-load-pilot`, `training`, `validation`, `model-test` и `final-comparison`. Выдавайте ID только из допустимого диапазона, не повторяйте уже занятые или зарезервированные значения, а также назначайте непересекающиеся роли train/validation/model-test/final-comparison. В один момент реестр изменяет только один ответственный. ID `1064` уже записан как неуспешная попытка Stage 3; он не считается новым независимым опытом.

Для каждого завершённого случая проверяйте `case-complete.json` и запускайте `nbiot.results.verifyCase`. MAT содержит полный результат и журналы; `_kpi.csv`, `_ue.csv`, `_radio.csv` и остальные таблицы удобны для просмотра. Не считайте `status=stopped`, `failed`, `partial` или `.staging-*` готовым случаем, даже если рядом есть частичные файлы.

## Ошибка и возврат данных

При отказе или тайм-ауте сохраните полный `host-run-*` вместе со `stdout.log`, `stderr.log`, кодом завершения, статусом, `report.mat` и выделенным ему диапазоном ID. Не удаляйте неудачные следы и не переиспользуйте те же ID без записи решения ответственного. Продолжайте только с результатами, прошедшими `verifyCase` и совпавшими по manifest; папка `.staging-*` не является точкой продолжения.

Верните весь каталог запуска и пакетный manifest, физический отчёт и журналы, реестр с назначениями и статусами, а для каждого принятого случая — MAT, все CSV и SHA-256. Если серия обучала или проверяла модель, верните также сам model bundle, его manifest и хеш. Не отправляйте учётные данные, ключи или частные настройки.

Для текущего ПК маршрут приведён в `docs/local-checks.md`. На другой машине после её отдельного допуска не используйте автоматически текущее локальное решение: сначала подтвердите окружение, ресурсный бюджет и новый Stage 2 evidence. Полный `runLoadPilot.ps1` на 100–5000 UE остаётся вне варианта 2.

## Что сохранить при будущей передаче результатов

Сохранить полный каталог `host-run-*`, физический отчёт, целевой журнал тестов, обновлённый реестр и новую запись допуска. Сверить SHA-256 первичных файлов; не заменять их сводной таблицей. Для возобновления расчётов считать завершёнными только те случаи, которые прошли `verifyCase` и совпали по версии. Каталог `.staging-*` точкой продолжения не является.

Пилот Stage 3 пока предназначен только для Static-режима. Проверенной на реальных независимых данных модели для обычного Adaptive нет. Старый development-набор из 40 окон и одного ID нельзя использовать как независимую выборку.
