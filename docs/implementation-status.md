- Модульный просмотр конфигурации/трафика, PHY/канала/планировщика и интеграции: [foundation-review.md](foundation-review.md), [phy-radio-review.md](phy-radio-review.md), [integration-review.md](integration-review.md).
- Обнаруженные ошибки в коде исправлены: ключевое слово `events` как имя свойства; несовпадение профиля калибровки; обновление кэша результатов; дедлайн DL с задержкой обработки; повтор Msg4 в пределах contention window; завершение RA при lifetime; отсчёт начала ACK.

Статический разбор подтверждает только свойства, проверяемые анализатором. Он не исполняет MATLAB, не устанавливает LTE Toolbox и не подтверждает размерности/CRC/BLER/время работы.

## Решения, принятые при стыковке

- **Msg4:** после неуспешного физического ACK BS сразу запрашивает повтор в пределах исходного contention window. Интервал 512 мс применяется к финальному data receipt. UE обрабатывает повтор Msg4 без сброса уже начатой передачи данных.
- **Приём:** общий guard 128 отсчётов; завершение приёма запланировано на `endTick + processingTicks + 1`, чтобы хвост канала был доступен. Конвенцию задержек нужно проверить на waveform в MATLAB.
- **NPRACH:** реализован поиск по CFO-сетке и интерполяция положения пика по соседним точкам. Первоначально описанный оцениватель по фазе повторов не реализован; точность текущего оценивателя и TA требуют проверки.
- **Оценка канала:** выбраны нечётные окна усреднения UL/DL; присутствие UCI требует когерентности DM-RS ≥0.5 и принятого кодового слова ≥0.8. После исправления выполнены проверки ACK/NACK и расширенная серия UCI по 20000 испытаний каждого типа. Совпадающие кодовые слова отдельных RNTI остаются ограничением UCI без CRC.
- **Серии:** по умолчанию только три независимые реализации на комбинацию нагрузки для пилотного профилирования. Для полной серии задать `options.realizationIds=0:99` после проверки одиночных цепочек. Это настройка будущего выполнения, не готовая статистика.
- **Датасет:** закрытые окна наблюдений экспортируются отдельно от ground truth. При остановке внутри окна неполные первичные события сохраняются в журналах, а строка этого окна в ML-таблицу не добавляется. На штатном горизонте завершается и последнее укороченное окно.
- **Waveform:** автоматический архив полных сигналов не реализован; `logging.saveWaveforms` зарезервирован для последующей диагностики. Это ограничение фиксируется явно.

## Реальные проверки на целевом ПК — завершённый пилот

- Исправлена совместимость NPRACH с `lteNPRACHInfo` R2025b: начало берётся из публичного `StartTime`, а не отсутствующего поля `Subframes`.
- Исправлено присутствие UCI: одной проверки DM-RS недостаточно для отличения чужого RNTI. Добавлена когерентность принятого кодового слова; ACK и NACK проверяются одинаково, CRC не имитируется. В расширенном тесте найдено совпадение: NACK RNTI 2103 принимается как ACK RNTI 100 в проверяемом ресурсе даже без шума. Частота ложных ACK оценивается отдельно; отсутствие таких событий не заявляется.
- Исправлена синхронизация DL по фазе принятых NRS. Приём не использует истинные задержки/канал/payload. В плоском канале прошли 24 проверки NPDCCH/NPDSCH при CFO −200/0/+200 Hz и задержках до 6.4 отсчёта.
- В 1800 многолучевых DL испытаниях при SNR 20 dB зарегистрирован один CRC-отказ NPDSCH, без ошибочного payload с принятым CRC. Повтор того же канала без шума успешен. Диапазон фазового оценивателя времени ограничен ±10.667 отсчёта.
- Полный набор исходной папки: 49/49 тестов прошли. Измерены 27 точек NPUSCH BLER (100 TB/точка, повторения 1/2/8); выполнены пять HARQ SNR-точек по 100 TB и десять NDI-reset проверок.
- Калибровка NPRACH принята: порог 0.0013808158865320679. Выполнены 20000 fit и две независимые validation серии по 20000 окон. Последняя серия: 2 ложных обнаружения, верхняя граница точного 95% интервала 0.000361187203 ≤0.001. Время 6153.904 s.
