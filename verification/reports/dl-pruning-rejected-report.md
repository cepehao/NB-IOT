# DL pruning: эксперимент отклонён

Дата: 2026-10-06.

Сначала прототип дал одинаковые выбранные PHY значения на 128 отдельных случаях, локальный helper ускорился в 3.37 раза, а unit-suite показал 115/115. Полная проверка 100 UE завершилась; case сохранён и verifyCase/resume прошёл без повторного расчёта.

Полное сравнение показало одинаковые config (после нормализации только outputFolder), KPI, actualTick, PHY summary, scenario, packet/RA logs, randomness, usage, статусы и счётчики. Верхнеуровневые observedLog и dataset различаются. Скрипт сохранил перечень checks и configMatched=true в dl-pruning-comparison-preassert.mat; CSV compare не выполнялся, потому что assert верно остановил при первом несоответствии. Следовательно, прототип не принят и ускорение всей системы не заявляется.

Восстановлены четыре исходных MATLAB-файла из pre-pruning-копии. Новому тесту TestDlTimingPruning оставлена отдельная копия в dl-pruning-rejected-candidate. Независимый UTF-8/SHA-256 пересчёт 115 активных MATLAB-файлов дал ту же сохранённую проверенную идентичность профиля и кэша: d67fc6cac7ac9f27852177b4a1baee2c70f98b3bfe5de2fa3507397d93d2ff46.

После восстановления полный suite не запускался: MATLAB в sandbox прерывается с System Error: File system inconsistency. Попытка запуска за sandbox была остановлена auto-review: рабочей среде не хватает кредитов для проверки эскалации. Обходить проверку нельзя. Нужен доступный внешний запуск MATLAB для продолжения unit/system проверки и вложенного сравнения. Исходный рабочий проект не редактировался.

Измеренные длительности 100 UE составили 1992.363 секунды до и 1488.018 после прототипа, но первый расчёт шёл одновременно с незаконченным 1000-UE прогоном и короткими диагностическими MATLAB задачами, а второй был последовательным. Из-за различия результата и нагрузки отношение времени не является доказательством ускорения.
