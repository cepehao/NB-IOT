# Проверка DL приёмника R3 — 2026-10-06

Исходный проект сохранён; патч относится только к optimization-candidate.

На development-каналах обнаружен воспроизводимый дефект внутри default DL delay range. Из16 CRC-отказов на9000 noisy exposures13 сохранялись без шума. Оценка задержки по фазовому наклону NRS могла принять фазу глубокого frequency-selective fade за сдвиг FFT-окна. Сохранён clean corner regression; до исправления он не декодировался.

Изменения:
1. Сдвиг FFT-окна выбирается по принятому cyclic prefix в публичном диапазоне −16..24 samples, ограниченном доступными guard.
2. Когерентность NRS во времени используется только для разрешения близких CP scores; истинная задержка/taps не поступают в RX.
3. Оценка канала сохраняет частотную селективность: FreqWindow1, TimeWindow1.
4. При этом LTE Toolbox возвращает нулевую оценку шума. Добавлен received-pilot residual estimator по повторным NRS каждого тона; noiseEstimate не подменяется eps при AWGN.
5. Фазовый наклон сохранён как диагностика, без принудительного перемещения FFT-окна.

Receiver revision: cp-nrs-coarse-selective-v2. Публичный физический профиль, waveform, MCS, repetitions, квоты и длительность горизонта не менялись. Результаты нового радиоалгоритма не должны совпадать с ошибочными старыми CRC/KPI.

## Ограничение скорости

Текущий coarse search вычисляет41 candidate-grid в полном guard-окне. Корректность сначала подтверждена, но это увеличивает цену одного DL приема. Выборочный NRS search/кэширование не включались без отдельного точного сравнения. Новые100/1000/5000 измерения нужны до заявления об общей скорости исправленной версии.
