# O3: целостность сохранения и resume

## Изменения в кандидате

- `saveResult(result,folder)` оставляет прежний MAT + шесть CSV интерфейс. Новый вариант `saveResult(result,folder,metadata)` пишет файлы только в пустой staging-каталог; отказ или прерывание оставляет его без признака принятого результата.
- MAT содержит result и компактный снимок конфигурации, receiver environment и KPI. SHA MAT вычисляется потоково, чтобы не читать большой файл целиком в память.
- Все шесть CSV читаются обратно, их заголовки/число строк сверяются с manifest, байты сравниваются со свежим экспортом таблиц в памяти. Проверяются packet/RA балансы и суммы по UE.
- `case-complete.json` с case key, config/source/calibration SHA, MATLAB/LTE environment, статусом, схемами/числом строк и SHA семи data-файлов записывается последним через временный файл.
- `runStaticSweep` использует отдельные каталоги `case key/run UUID`; resume принимает только completed attempt с подходящими версиями и всеми хешами. Повреждённые и устаревшие попытки остаются для диагностики, новый результат пишется в отдельный каталог. `manifest.csv` обновляется coordinator-ом через temp + атомарное перемещение.
- Вызовы старого двухаргументного `saveResult` оставлены совместимыми; для тестирования runner принимает необязательный `runExperimentFcn`.

## Границы

Параллельный запуск ещё не подключён; `runStaticSweep` остаётся последовательным. O3 хранит файлы прерванной попытки, но resume не принимает её без корректного completion marker и полного совпадения текущих версий.
