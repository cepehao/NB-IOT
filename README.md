# Симулятор NB-IoT на MATLAB — v2

Эта ветка содержит новую MATLAB-версию. Предыдущий проект для Engee сохранён отдельно: [версия Engee в main](https://github.com/cepehao/NB-IOT/tree/main). Между версиями можно переключаться через список веток на GitHub. Готовый выпуск: [v2.0.0](https://github.com/cepehao/NB-IOT/releases/tag/v2.0.0).

Это исследовательский симулятор одной соты NB-IoT. Он моделирует сигналы на физическом уровне: устройства пытаются получить доступ к сети, передают пакет, а базовая станция принимает и декодирует его. По результатам можно посмотреть успешность доступа, доставку, задержки, ошибки и использование ресурсов.

Сейчас работает версия **Static**: вероятность доступа и доли ресурсов RA/DT фиксированы. ML, адаптивное управление и графический интерфейс относятся к следующему этапу. Запуск выполняется командами в MATLAB.

## Что нужно для запуска

| Компонент | Для чего нужен |
|---|---|
| MATLAB **R2025b** | Версия, на которой проверен проект |
| **LTE Toolbox** той же версии | Формирование и приём физических сигналов NB-IoT |
| Parallel Computing Toolbox | Только для необязательных параллельных серий |

Для обычного запуска достаточно MATLAB и LTE Toolbox. Python, Simulink и видеокарта для него не требуются. Основная версия считает на CPU.

Проект проверен на Windows x64. Совместимость с другими версиями MATLAB и ОС нужно проверить на конкретной машине. Измерения производительности сделаны на i5-10400F с 32 ГиБ RAM; это сведения о тестовом ПК, а не установленный минимум памяти.

### Установка MATLAB

1. Откройте [MathWorks Downloads](https://www.mathworks.com/downloads/) и войдите в аккаунт, которому доступна лицензия MATLAB. Для университетской или корпоративной лицензии используйте соответствующий аккаунт.
2. Выберите выпуск **R2025b** и скачайте установщик для вашей ОС.
3. При установке выберите **MATLAB** и **LTE Toolbox**. Для параллельного режима дополнительно выберите **Parallel Computing Toolbox**.
4. Завершите установку и активацию. Откройте MATLAB.

Если MATLAB уже установлен, убедитесь, что доступен именно LTE Toolbox:

~~~matlab
version('-release')
ver('lte')
which lteNPRACH
~~~

Первая команда должна показать 2025b, вторая — сведения о LTE Toolbox, третья — путь к функции. Пустой ответ означает, что нужный компонент не найден. Если лицензия организации не предлагает LTE Toolbox, доступ нужно уточнить у её администратора.

Официальная инструкция: [установка MATLAB R2025b](https://www.mathworks.com/help/releases/R2025b/install/ug/install-products-with-internet-connection.html).

## Как получить и открыть проект

Откройте [MATLAB-версию в ветке v2](https://github.com/cepehao/NB-IOT/tree/v2). Убедитесь, что в списке веток выбрано **v2**, затем нажмите **Code → Download ZIP**. Ещё проще скачать NB-IOT-v2.0.0.zip со [страницы выпуска](https://github.com/cepehao/NB-IOT/releases/tag/v2.0.0). Распакуйте в обычную папку, в которую у вас есть право записи. Репозиторий закрытый: для скачивания войдите в GitHub-аккаунт, которому предоставлен доступ.

Если используете Git, выполните в терминале:

~~~powershell
git clone --branch v2 --single-branch https://github.com/cepehao/NB-IOT.git
~~~

В корне проекта должны находиться:

~~~text
setupProject.m
README.md
src/
configs/
examples/
experiments/
tests/
docs/
results/nprach-calibration.mat
~~~

В MATLAB выберите эту папку в **Current Folder**. Корень — папка, в которой лежит setupProject.m. Далее все команды из инструкции выполняются в **Command Window** MATLAB, если явно не указан другой способ.

~~~matlab
setupProject();
environment = checkEnvironment(true);
~~~

setupProject подключает код проекта. checkEnvironment проверяет доступность функций LTE Toolbox и выполняет короткие проверки передачи/декодирования сформированных сигналов.

При успехе функция завершается без ошибки, а:

~~~matlab
environment.roundtripExecuted
environment.roundtrip
~~~

показывают выполненную проверку и успешные результаты NPUSCH, NPDCCH, NPDSCH и UCI. Если проверка остановилась с ошибкой, сначала разберитесь с ней по разделу «Если что-то не запускается».

## Первая проверка: одно устройство

Начните с небольшого примера. В нём один UE находится близко к базовой станции, передаёт пакет 200 байт и проходит всю цепочку доступа и доставки. Это проверка исправности цепочки при хорошем сигнале, а не измерение качества всей соты.

~~~matlab
calibrationFile = fullfile(pwd, 'results', 'nprach-calibration.mat');
assert(isfile(calibrationFile), 'В папке results отсутствует nprach-calibration.mat.');

result = runSingleUe(calibrationFile);
assert(strcmp(result.status, 'completed'), 'Расчёт не завершился успешно.');
assert(result.kpiSummary.delivered == 1, 'Тестовый пакет не доставлен.');
assert(result.kpiSummary.deliveredPayloadBits == 1600, 'Неверный объём доставленных данных.');
~~~

Для этого примера ожидаются:

- status: completed;
- created: 1;
- delivered: 1;
- deliveredPayloadBits: 1600.

Результат сохраняется в **results/single-ue**: MAT-файл и шесть CSV. Повторный вызов этого демонстрационного примера обновляет файлы в той же папке. Для хранения отдельных попыток и возобновляемых серий используйте следующий раздел.

Время расчёта зависит от ПК. **5 секунд в конфигурации — время внутри модели**, фактический расчёт может занимать значительно дольше.

## Запуск автоматических тестов

После успешного примера выполните:

~~~matlab
testResults = runtests('tests', 'IncludeSubfolders', true);
disp(table(testResults));
assertSuccess(testResults);
~~~

assertSuccess завершается без ошибки, когда все тесты прошли. В проверенной текущей версии **112 тестов**. Они проверяют конфигурацию, случайные потоки, календарь и квоты, кодирование, приём, HARQ, состояния, сохранение результатов и повторяемость.

Полный набор выполняет реальные физические расчёты и может занимать несколько минут. Прохождение этого набора подтверждает проверенные сценарии; полная научная приёмка ТЗ требует ещё статистических серий.

## Небольшая серия с сохранением и возобновлением

Пример ниже выполняет три независимых расчёта с одним UE и сохраняет каждую принятую попытку отдельно:

~~~matlab
options = struct( ...
    'counts', 1, ...
    'burstDurations', 100, ...
    'realizationIds', 0:2, ...
    'calibrationFile', calibrationFile, ...
    'outputFolder', fullfile(pwd, 'results', 'my-first-series'), ...
    'resume', true);

manifest = runStaticSweep(options);
disp(manifest);
~~~

Чтобы продолжить ту же серию, повторите вызов с теми же options. Завершённые результаты используются повторно только после проверки файлов, конфигурации, версии кода, калибровки и среды. Незавершённый расчёт случая начинается заново; состояние внутри прерванного расчёта на диск не восстанавливается.

realizationIds задаёт независимые внешние случайные реализации. Повтор того же ID воспроизводит тот же сценарий и не считается новым независимым опытом.

Всегда задавайте counts, burstDurations и realizationIds явно. Вызов runStaticSweep без параметров запускает сетку из **45 случаев**, включая 5000 UE; для первой проверки это слишком большая работа.

### Параллельный вариант — по желанию

При наличии Parallel Computing Toolbox вместо последовательного вызова можно выполнить:

~~~matlab
options.numWorkers = 2;
options.outputFolder = fullfile(pwd, 'results', 'my-first-series-parallel');
manifest = runStaticSweepParallel(options);
~~~

Workers выполняют отдельные реализации. Это ускоряет серию; один расчёт не делится между ними. Два процесса — исходная настройка для проверки памяти и времени на вашей машине.

## Где смотреть результаты

При запуске серии в её каталоге появляется manifest.csv. Он содержит число UE, длительность всплеска, ID реализации, статус, время расчёта и путь к MAT-файлу.

Пример чтения принятого результата:

~~~matlab
resultFile = char(string(manifest.resultFile(1)));
saved = load(resultFile, 'result');
disp(saved.result.status);
disp(saved.result.kpiSummary);

integrity = nbiot.results.verifyCase(fileparts(resultFile));
assert(integrity.passed, strjoin(integrity.errors, '; '));
~~~

verifyCase проверяет пакет файлов серии: MAT, шесть CSV и завершающий case-complete.json. Демонстрационный runSingleUe сохраняет более простой экспорт; для него эта проверка пакета серии не применяется.

| Данные | Что содержат |
|---|---|
| MAT | Конфигурация, сценарий, журналы, KPI, таблицы датасета, статус и ошибки |
| CSV с окончанием _ue | Число созданных, доставленных, потерянных и незавершённых пакетов по UE |
| _kpi | KPI по временным окнам |
| _observations | Признаки, доступные базовой станции |
| _targets | Истинные показатели для офлайн-анализа и будущего обучения |
| _resources | Использование ресурсных бюджетов |
| _split | Принадлежность реализации к разбиению датасета |

Статус completed означает, что расчёт дошёл до конца горизонта. Он не означает доставку всех пакетов. dropped — потерянные пакеты, unfinished — ещё не завершённые к концу моделирования, failed — ошибка расчёта. Нагрузочный сценарий может быть перегружен при исправном симуляторе.

## Как перейти к большей нагрузке

Для одного обычного расчёта измените параметры серии:

~~~matlab
options.counts = 100;
options.realizationIds = 0;
options.outputFolder = fullfile(pwd, 'results', 'load-100');
manifest = runStaticSweep(options);
~~~

Затем можно задать counts = 1000 и новый outputFolder. Начинайте с одного случая: в прежних измерениях нагрузка 100 UE занимала десятки минут, 1000 UE — больше часа. Эти времена зависят от версии радиоприёмника, оборудования и числа одновременно работающих процессов.

Параметры базовой модели: горизонт 5 с, шаг 1 мс, пакет 200 байт, seed 42, Static P=1, доли ресурсов RA/DT 10/90. Конфигурация создаётся функцией nbiot.config.defaultConfig. Для другого трафика есть burst, periodic и poisson.

## Зачем нужен файл калибровки

results/nprach-calibration.mat содержит проверенный порог детектора NPRACH для текущего физического профиля. Он входит в передаваемую версию и нужен для обычного запуска. Используйте его для воспроизведения этой версии.

Не подставляйте порог вручную вместо загрузки отчёта. При изменении детектора, частоты дискретизации или проверяемого физического профиля потребуется новая калибровка и проверка помех. Это отдельный продолжительный эксперимент, который не нужен для первого знакомства с проектом.

Если файл отсутствует или несовместим, получите полную копию этой версии. Файлы от старой версии приёмника могут не подойти.

## Если что-то не запускается

| Симптом | Что проверить |
|---|---|
| MATLAB не находит setupProject или runSingleUe | Выбрана ли папка с setupProject.m; выполнен ли setupProject |
| Не найден пакет nbiot или вызывается старая функция | Выполните which setupProject -all и which nbiot.runExperiment -all; оставьте в MATLAB Path одну версию проекта |
| Не найдена функция lte... | Выполните ver('lte') и which lteNPRACH; проверьте установку и лицензию LTE Toolbox |
| Ошибка Calibration | Проверьте наличие results/nprach-calibration.mat и соответствие его текущей версии кода |
| Не создаются файлы | Проект и выбранный outputFolder должны быть доступны для записи |
| Параллельный режим недоступен | Проверьте Parallel Computing Toolbox; последовательный runStaticSweep можно использовать отдельно |
| File system inconsistency при запуске через агент | Запустите MATLAB непосредственно на ПК. На тестовой машине такая ошибка возникала в ограниченной песочнице; сама установка MATLAB вне неё работала |

Если ошибка повторяется, пришлите коллегам полный текст и стек, результаты version / ver('lte'), команду запуска и конфигурацию. Для длинного запуска можно сохранить вывод:

~~~matlab
diary(fullfile(pwd, 'results', 'diagnostic-log.txt'));
% Выполните команду, которая вызывает ошибку.
diary off;
~~~

## Состояние проекта и подробная документация

Инструкция проверена 6 октября 2026 года в новой папке на Windows с MATLAB R2025b: проверка среды, доставка одного пакета 200 байт, все 112 тестов, серия из трёх расчётов и её повтор с resume прошли. Для других машин время выполнения и доступность лицензий могут отличаться.

Работают Static-ядро, физическая процедура доступа и передача данных, календарь ресурсов, HARQ, KPI, экспорт и независимые параллельные серии. Приняты оптимизации календаря и кэша неизменяемых PHY-профилей.

Серии полной научной приёмки ещё не завершены. В частности, остаются большие финальные нагрузки и расширенная статистика. ML, адаптивные политики и GUI пока не входят в эту версию. Физическая неоднозначность UCI и границы проверенных радиосценариев описаны в документации.
